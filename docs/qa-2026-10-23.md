# Sitemap Creator regression QA — October 23, 2026

Scope: new merchant installation, dashboard, generation, saved settings,
publication, theme block, consent, and cleanup. Baseline: `382a600`.

## Evidence and limitations

The automated suite invokes actual model and route-handler code with mocked
Shopify, database, and email-provider boundaries. These tests are regression
coverage, not proof of a fresh OAuth installation or production database load.
Liquid fixtures render the extension and snippet and instrument each loop to
reject more than 50 iterations. Native Shopify theme rendering still needs a
live smoke test.

The earlier nested-menu hotfix is already in production. The merchant confirmed
that the DFND USA dashboard loads after that fix. No DFND settings, sitemap,
theme, email preferences, or installation were changed during this QA pass.

The test-store browser reached Shopify Admin, but its embedded app document
stalled in browser-tool response handling. This does not establish a production
application failure. Vercel runtime-log endpoints were inaccessible to the
connected account, so no live runtime-stack claim is made here.

## Fixes in this QA release

- Recover first-load unique-key races without replacing saved settings.
- Keep optional menu/email outages from crashing the dashboard while preserving
  Shopify authentication recovery responses.
- Provide a recoverable dashboard error view and preserve the original sync
  error if saving its failure status also fails.
- Preserve explicitly empty section selections, normalize settings, and commit
  settings with the completed snapshot.
- Reject failed/partial GraphQL responses and stalled pagination.
- Escape merchant HTML and Liquid delimiters, reject action URLs, and tolerate
  malformed optional dates.
- Publish Shopify content before committing the database snapshot, preserving
  the last database snapshot if Shopify rejects publication.
- Publish chunks, configuration, and manifest in one atomic Shopify mutation.
  Preflight the 25-field, JSON-size, and request-size limits before writing;
  unusually large data receives a recoverable size error instead of a partial
  theme update. Both ordinary and multilingual 5,000-link fixtures fit.
- Correct empty-sitemap and password-protection detection; bound check duration.
- Prevent proxy access after the installed session has gone away.
- Preserve failed remote erasure for webhook retry and keep unsubscribe retry
  on the unsubscribe path.
- Handle malformed signed email-provider payloads without an application crash.
- Render large theme chunks within Shopify's loop limit and honor saved false
  display settings.

## Validation

All 152 tests in 20 files pass, including all six required Liquid fixtures.
TypeScript checking, ESLint, and the production bundle build pass. The release
record contains the exact commit and Vercel deployment.
The production bundle is built locally with a dummy database URL using
`react-router build`; the local QA command does not run production migrations.

Official Shopify Toolkit validation passes for the changed Polaris App Home
markup and both changed Liquid files. Liquid validation used the Toolkit's
exact dependencies in an isolated temporary runtime with networking disabled;
the application dependency graph was not changed for that validator.

## Release and follow-up gates

GitHub/Vercel deploys the web backend. Shopify's theme extension requires its
own app-version release; a successful Vercel build does not release Liquid.
Do not report the extension fix as live until that release succeeds.

Before calling the complete installation flow verified, use a disposable test
installation to install/open, generate, change/save/reload settings, inspect the
proxy and theme block, and test uninstall/reinstall. Email tests in this pass
use mocks and send no real messages.

Delayed uninstall/privacy cleanup arriving after a rapid reinstallation is an
unverified lifecycle risk. The current data model has no installation generation
to distinguish an old cleanup delivery from a new installation. No speculative
schema migration was included in this QA patch.

Shopify publication and database saving are separate systems: a lost response
after Shopify commits, or a later database failure, can leave a newer theme
snapshot than the database-backed proxy. The app reports the operation as failed
and a successful generation reconciles them; this patch does not claim a
distributed transaction across Shopify and the database.
