## Fixes in this QA release

- Recover first-load unique-key races without replacing saved settings.
- Keep optional menu/email outages from crashing the dashboard while preserving
  Shopify authentication recovery responses.
- Provide a recoverable dashboard error view and preserve the original sync
  error if saving its failure status also fails.
- Preserve explicitly empty section selections, normalize settings, and commit
  settings with the completed snapshot.
- Reject failed/partial GraphQL responses and stalled pagination.
- Escape merchant HTML and Liquid delimiters, reject action URLs, and tolerate
  malformed optional dates.
- Publish Shopify content before committing the database snapshot, preserving
  the last database snapshot if Shopify rejects publication.
- Publish chunks, configuration, and manifest in one atomic Shopify mutation.
  Preflight the 25-field, JSON-size, and request-size limits before writing;
  unusually large data receives a recoverable size error instead of a partial
  theme update. Both ordinary and multilingual 5,000-link fixtures fit.
- Correct empty-sitemap and password-protection detection; bound check duration.
- Prevent proxy access after the installed session has gone away.
- Preserve failed remote erasure for webhook retry and keep unsubscribe retry
  on the unsubscribe path.
- Handle malformed signed email-provider payloads without an application crash.
- Render large theme chunks within Shopify's loop limit and honor saved false
  display settings.

Delayed or retried cleanup is a **code-identified risk, not a failure observed
in this test**: the current cleanup handlers delete by store domain and have no
installation-generation guard. Shopify's [2026-04 shop/redact reference](https://shopify.dev/docs/api/webhooks/2026-04?accordionItem=webhooks-shop-redact)
states that the normal redaction event is not emitted after the app is
reinstalled; a normal fast reinstall cancels that scheduled redaction. This
qualifies the earlier broad warning: it is not an assertion that every rapid
reinstall receives shop/redact. Already delayed/retried cleanup has no local
generation guard. No speculative lifecycle or schema change was included.

Shopify publication and database saving are separate systems: a lost response
after Shopify commits, or a later database failure, can leave a newer theme
snapshot than the database-backed proxy. The app reports the operation as failed
and a successful generation reconciles them; this patch does not claim a
distributed transaction across Shopify and the database.
